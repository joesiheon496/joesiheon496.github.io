## 한 줄 요약

센서 간(LiDAR-카메라) 캘리브레이션이 아니라 **LiDAR-차량(vehicle frame) 오정렬**을 다룬다. 핵심 관찰은 단순하다:

> **정지한 물체 위의 점은 에고 모션을 정확히 거꾸로 따라 움직여야 한다.** LiDAR가 차량에 대해 회전 오정렬되어 있으면, 연속 프레임(t=k, t=k+1) 사이의 scene flow에 **거리에 비례하는 체계적 편향**이 남는다. 예: yaw 오차는 전진량에 비례하는 횡방향 흐름 성분을 만든다.

이 편향을 읽으면 IMU·GPS·카메라 같은 추가 센서 없이, 점군 시퀀스만으로 오정렬을 탐지할 수 있다.

## 배경 / 왜 읽었나

- 기존 캘리브레이션 연구는 대부분 **센서-센서**(LiDAR-카메라 등) 외부 파라미터에 집중한다. 개별 센서가 **차량 프레임에 대해** 틀어지는 문제 — 진동·충격·장착 오차로 실제 운행에서 흔히 생기는 — 의 탐지는 공백이었다.
- 캘리브레이션 서베이를 하면서 "t=k, t+1 연속 프레임 정보로 최적화/추정하는 논문"을 찾다가 발견했다. 모션 기반 캘리브레이션 계보(hand-eye, AX=XB)의 학습 시대 버전으로 읽힌다 — 다만 **보정이 아니라 탐지**가 목표다.

## 방법

### 파이프라인

```text
[1단계 전처리]  지면 제거 → 좌표 변환 → 점군 증류(distillation) → 동적 물체 제거
                 (정지 물체만 남긴다 — 핵심 가정의 성립 조건)

[2단계 탐지]    NSFP로 연속 프레임 흐름장 생성
                 ├─ 학습 특징: 흐름장 → 인코더 → max/mean pool 전역 특징
                 └─ 기하 특징: 수제 기술자 237차원
                 → 결합 → 이중 분류 헤드
                    ├─ Global Head: 오정렬 있음/없음 (이진)
                    └─ Axis Head:  roll/pitch/yaw 축별 이진 판정
```

흐름 추정기는 [NSFP]({{< ref "/posts/nsfp" >}})를 그대로 쓴다 — 학습 데이터가 필요 없는 test-time 최적화라, 탐지 프레임워크 전체가 흐름 라벨 없이 성립한다.

### 수제 기하 기술자 (237차원)

축별로 세 계열:

| 계열 | 내용 |
|---|---|
| 크기(magnitude) | 흐름 노름의 평균·표준편차 |
| 각도(angle) | 흐름 성분 간 arctan 비율의 히스토그램 — 72 bin × 5° 해상도 |
| 회전(rotation) | 점 위치 벡터와 흐름 벡터의 외적 통계 (평균·표준편차) |

합계 21 + 3×72 = **237차원**. 회전 오정렬이 만드는 "거리에 비례하는 접선 방향 흐름"을 외적 통계가 직접 포착하는 설계다.

### 학습 설정

- 회전 오차를 \(\alpha_{err} \sim U([-5.0,-0.5]^\circ \cup [0.5,5.0]^\circ)\) 로 샘플링해 오정렬 데이터를 합성. 0 근방을 제외해 난이도 구간(easy/medium/hard)을 구성.
- 데이터셋: nuScenes.

## 결과

| 축 | 정확도 | 정밀도 | 재현율 |
|---|:---:|:---:|:---:|
| Roll (φ) | **87.04%** | 86.60% | 78.50% |
| Pitch (θ) | 60.81% | 55.87% | 73.50% |
| Yaw (ψ) | 76.06% | 63.82% | 88.73% |

- 전역(있음/없음) 탐지 정확도 **81.16%**. 큰 오차([±2°, ±5°])에서는 **90.27%**, 미세 오차([±0.5°, ±2°])에서는 73.81%.
- 비교 베이스라인은 없음 — "LiDAR-to-vehicle 오정렬 탐지의 첫 프레임워크"로서 벤치마크를 세우는 논문이다.

## 한계

1. **Pitch가 약하다** (단독 오차 시 24.73%). pitch 오차는 흐름에 공간적으로 균일한 상하 성분을 만들어, 거리 의존 패턴을 읽는 이 방법의 신호가 약해진다.
2. **동적 물체 제거에 데이터셋 GT를 사용** — "추가 센서 불필요" 주장이 완전히 자립적으로 검증된 것은 아니다.
3. **회전만 다룬다.** 병진 오정렬은 미검증.
4. nuScenes 단일 데이터셋 — 일반화 미확인.

## 메모

- **탐지에서 멈춘다는 게 가장 큰 여지다.** 흐름 편향의 방향·크기는 오차의 축·부호·크기와 기하적으로 연결되어 있으므로, 분류가 아니라 **회귀 → 보정(re-calibration)** 으로 확장하는 것이 자연스러운 다음 단계로 보인다. NSFP가 미분가능하므로 오차각을 직접 최적화 변수로 두는 구성도 가능할 것.
- 캘리브레이션 서베이 관점에서: 모션 기반 계보(연속 프레임 포즈로 AX=XB를 푸는)와 학습 기반 계보의 교차점에 있는 논문. "교란-복원" 합성 프로토콜을 쓴다는 점은 기존 관행의 한계를 그대로 공유한다.
- 정지 물체 가정이 성립하려면 전처리(동적 제거)가 강건해야 한다 — 실전 배치의 실질 병목은 여기일 듯.

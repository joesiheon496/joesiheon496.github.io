## 한 줄 요약

**컬러 점군 업샘플링을 2D 이미지 복원 문제로 바꿔 푼다.** 희소 점군을 여러 시점에서 렌더링 → 이미지를 조밀하게 복원 → 그 이미지들을 **3D Gaussian Splatting의 감독 신호**로 써서 다시 3D 점군으로 되돌린다. 3DGS가 2D와 3D를 잇는 다리 역할을 한다.

노리는 것은 성능 수치가 아니라 **규모**다. 기존 방법은 GPU 메모리 때문에 점군을 패치로 쪼개 처리하는데, 그 경계에서 불연속이 생긴다. 이 방식은 **소비자용 GPU 한 장(RTX 3090)으로 200만 점짜리 점군을 통째로** 처리한다.

## 배경 / 문제

컬러 점군은 XYZ에 RGB가 붙은 6차원 데이터다. 로봇 인지·시맨틱 매핑에서 색은 형상만큼 중요한 정보인데, 기존 업샘플링 연구는 대부분 **무채색 점군의 기하만** 다뤘다.

더 실질적인 문제는 **패치 분할**이다.

> MLP·EdgeConv 기반 방법들은 연산량 때문에 대개 **1,024점 미만의 패치**로 학습된다. 큰 점군은 잘라서 넣고 결과를 다시 붙여야 하는데, 이때 **패치 사이에 불연속**이 생긴다. 사람이 눈으로 보는 컬러 점군에서는 이게 곧바로 품질 저하로 이어진다.

## 핵심 아이디어

> 점군을 직접 다루기 어려우면, **잘 다룰 수 있는 도메인(2D 이미지)** 으로 옮겨 풀고 되돌린다.

파이프라인은 두 덩어리다.

```text
[데이터 준비]
  희소 점군 ──(듀얼 스케일 렌더링)──> 2장의 렌더 이미지 ──(복원망)──> 조밀 렌더 이미지
  희소 점군 ──(가우시안 보간)──────> R배 보간 점군

[3DGS 업샘플링]
  조밀 렌더 이미지 + 카메라 포즈 + 보간 점군 ──(3DGS 최적화)──> 조밀 컬러 점군
```

### ① 듀얼 스케일 렌더링 — 점 크기 딜레마

Open3D로 점군을 렌더링하는데, **점 크기(PS)를 얼마로 할지**가 골치다.

| 점 크기 | 장점 | 단점 |
|---|---|---|
| **PS = 1** | 원본 정보를 최대한 보존 | 희소 점군에서는 **뒤쪽 점이 앞으로 비쳐 보인다** → 복원망이 앞뒤 관계를 헷갈림 |
| **PS = R (크게)** | 전경/배경 구분이 뚜렷 | 점끼리 겹쳐 **정보가 소실** |

논문의 답은 단순하다. **둘 다 쓴다.** 두 크기로 렌더링한 이미지를 채널 방향으로 이어 붙여 6채널 입력으로 만든다. 복원 백본은 경량성을 고려해 BRNet(FFDNet에 mean shift 모듈을 추가한 것)을 쓰고, 입력 채널만 6채널로 확장했다.

배경이 대부분 흰색인 렌더 이미지 특성을 반영해 **전경/배경 손실 가중을 나눈다**.

```text
L_Res = α · (1/N_w) Σ_{i∈W} |I_h − Î_h|  +  β · (1/N_o) Σ_{j∈O} |I_h − Î_h|
        W = 흰 배경 픽셀 (α = 0.3)          O = 전경 픽셀 (β = 0.7)
```

### ② 가우시안 보간 — 점 개수를 미리 확정한다

3DGS를 그냥 돌리면 가우시안 개수가 최적화 중에 바뀌므로 "정확히 R배"를 만들 수 없다. 그래서 **입력 단계에서 개수를 못 박는다.**

```text
f = μ + σ·ε ,  ε ~ N(0, 1)
  기하: σ = 0.25 × 점군 스텝 크기
  색상: σ = 0            ← 색은 흔들지 않는다
```

각 점마다 R번 재매개변수화 샘플링해서 R×N개의 보간 점군 `P_gi`를 만든다. 색상 σ를 0으로 두는 건 **색은 원본을 그대로 복제하고 이후 3DGS 최적화에서만 다듬겠다**는 뜻이다.

### ③ vanilla 3DGS에 가한 네 가지 수술

여기가 이 논문의 실질적 기여다. 원본 3DGS는 신규 시점 렌더링이 목적이라 점군 업샘플링에 그대로 쓸 수 없다.

| 수정 | 이유 |
|---|---|
| **clone·split·prune 비활성화** | 가우시안 개수를 고정해 정확히 R배 출력 보장 |
| **스케일 균일화** | 매 반복마다 전체 평균 스케일을 계산해 모든 점에 동일 할당 — "모든 점은 같은 크기로 렌더된다"는 사전 지식 반영 |
| **불투명도 = 1 고정** | RGB만 다루므로 투명도 최적화 불필요 |
| **점군 정규화 항 추가** | 색은 `P_gi`와의 L1, 기하는 원본 희소 점군과의 **Chamfer 거리** |

기하 감독에는 스케줄이 걸려 있다. **초기 M 스텝 동안 256스텝마다 CD를 넣고, M 이후에는 기하 최적화를 끄고 색상만 다듬는다.**

```text
L_Up = λ₁·L1(I_r, I_h) + λ₁·L1(P^c_gi, P^c_ds) + λ₂·L_D-SSIM(I_r, I_h)
       (+ λ₃·L_CD(P^g_sp, P^g_ds)   ...  step % 256 == 0 이고 step ≤ M 일 때만)
```

## 결과

WPC 데이터셋에서 25개 10-bit 컬러 점군을 골라(41만~288만 점) 몬테카를로로 1/4 다운샘플한 뒤 4× 복원. 테스트는 100만 점 이상 5개(Cake 249만, Cauliflower 194만, House 157만, Litchi 104만, Pumpkin 134만).

지각 품질은 32개 임의 시점에서 렌더링해 측정한다. 논문은 **IW-SSIM이 사람의 주관 평가와 가장 잘 맞는다**며 이걸 주 지표로 권한다.

| 방법 | PSNR↑ | SSIM↑ | LPIPS↓ | IW-SSIM↑ | CD↓ (×10⁻⁵) | HD↓ (×10⁻²) |
|---|:--:|:--:|:--:|:--:|:--:|:--:|
| Input (희소) | 13.121 | 0.864 | 0.163 | 0.548 | 0.188 | 0.771 |
| 3DGS (vanilla) | 10.703 | 0.845 | 0.202 | 0.434 | 8.464 | 7.645 |
| [Grad-PU]({{< ref "/posts/grad-pu" >}}) | 20.708 | 0.913 | 0.088 | 0.790 | 0.125 | 0.753 |
| **GaussianPU** | **23.684** | **0.932** | **0.043** | **0.876** | **0.124** | **0.701** |

읽는 법:

- **지각 지표에서는 확실한 우위.** IW-SSIM 0.790 → 0.876, LPIPS 0.088 → 0.043(절반). 입력 대비 IW-SSIM 59% 개선.
- **기하 지표에서는 사실상 무승부.** CD 0.125 → 0.124다. 즉 이 논문의 이득은 **색·지각 품질과 균일성**이지 기하 정확도가 아니다.
- **vanilla 3DGS는 입력보다도 나쁘다** (IW-SSIM 0.434 < 0.548). 3DGS를 그냥 갖다 쓰면 안 되고, 위의 네 가지 수정이 있어야 성립한다는 걸 보여주는 숫자.

### 절제 실험

**듀얼 스케일 복원** (렌더 이미지 품질 기준):

| 복원 입력 | PSNR↑ | SSIM↑ | LPIPS↓ | IW-SSIM↑ |
|---|:--:|:--:|:--:|:--:|
| 단일 스케일 (PS=1) | 23.765 | 0.939 | 0.070 | 0.807 |
| 단일 스케일 (PS=4) | 26.556 | 0.950 | 0.061 | 0.882 |
| **듀얼 스케일** | **28.432** | **0.961** | **0.052** | **0.926** |

더 나은 단일 스케일(PS=4) 대비 PSNR +1.876 dB, IW-SSIM +0.044. 두 크기가 **상보적**이라는 주장이 확인된다.

**3DGS 수정 누적**:

| 구성 | PSNR↑ | IW-SSIM↑ | CD↓ (×10⁻⁵) | HD↓ (×10⁻²) |
|---|:--:|:--:|:--:|:--:|
| 3DGS (Base) | 10.703 | 0.434 | 8.464 | 7.645 |
| + 가우시안 보간·개수 고정 | 14.404 | 0.474 | 0.172 | 1.11 |
| + 불투명도 고정 | 14.872 | 0.605 | 0.181 | 0.753 |
| **+ 스케일 균일화** | **23.681** | **0.876** | **0.124** | **0.701** |

**개수 고정만으로 CD가 8.464 → 0.172로 49배 개선**된다. 기하 붕괴의 주범이 3DGS의 자유로운 densify/prune이었다는 뜻. 그리고 스케일 균일화가 지각 품질을 크게 끌어올린다(IW-SSIM 0.605 → 0.876).

## 읽으면서 걸린 것들

정리하면서 확인한, 논문 내부의 불일치와 해석상 주의점:

1. **절제 실험 본문과 표가 어긋난다.** 본문은 "IW-SSIM이 최고 0.900에 도달, 기준선 대비 107% 개선"이라고 쓰는데 Table III의 최고값은 **0.876**이다. 또 본문은 "이 세 가지 개선은 기하 품질을 높이지 못하고, 점군 정규화를 넣으면 지각 품질이 약간 떨어지는 대신 기하가 크게 좋아진다"고 서술하는데, 표에서는 마지막 행이 **모든 지표에서 최고**다. 표와 서술이 다른 실험을 가리키는 것으로 보인다. 인용 시 **표 값을 쓰는 게 안전**하다.
2. **Table I과 Table III의 같은 설정 값이 미세하게 다르다** (PSNR 23.684 vs 23.681).
3. **Grad-PU 비교가 다소 불리하게 설정되어 있다.** Grad-PU는 기하 전용 방법이라 색이 없는데, 논문은 **최근접 이웃 보간으로 색을 입혀** 비교했다. 색 품질 지표에서 밀리는 건 당연한 면이 있다. 반대로 **기하 지표(CD)에서는 사실상 동률**이라는 점이 오히려 공정한 비교 결과에 가깝다.
4. **수식 (2)의 K는 내부 파라미터(intrinsics)인데 본문은 "카메라 외부 파라미터"라고 쓴다.** 오타로 보인다. 외부 파라미터는 바로 뒤의 `T ∈ ℝ⁴ˣ⁴`.
5. **입력이 GT를 랜덤 다운샘플한 것**이라, 실제 센서의 희소·불균일 패턴과는 다르다. 로봇 응용을 표방하지만 실측 데이터 실험은 없다.

## 구현 세부

| 항목 | 값 |
|---|:--:|
| 복원망 학습 | 100 epoch, Adam, lr 1e-4, weight decay 1e-5 |
| 손실 가중 | α (배경) 0.3 / β (전경) 0.7 |
| 3DGS 최적화 | 50,000 iteration |
| 기하 감독 한계 `M` | 20,000 (256스텝마다 CD) |
| λ₁ (L1) / λ₂ (D-SSIM) | 0.8 / 0.2 (vanilla 3DGS와 동일) |
| λ₃ (CD) | 입력 점 개수의 절반 |
| 구면조화 차수 | 0 (RGB만) |
| GPU | NVIDIA GeForce RTX 3090 1장 |

## 메모

- **"같은 가우시안, 전혀 다른 용법"** — [PU-Gaussian]({{< ref "/posts/pu-gaussian" >}})은 각 점의 국소 이웃을 이방성 가우시안으로 **모델링해 거기서 점을 뽑는다**. GaussianPU는 가우시안을 **렌더링 프리미티브**로 쓰고 2D 감독으로 최적화한다. 이름이 비슷해서 헷갈리기 쉽지만 공통점은 "3DGS의 파라미터화를 빌렸다"는 것뿐이다.
- **핵심 통찰은 "감독 신호를 어디서 얻느냐"** 다. 기존 업샘플링은 3D 정답 점군에서 감독을 받는다. 여기서는 **2D 복원 이미지**가 감독이 된다. 2D 이미지 복원은 수십 년치 축적이 있고 GPU 효율도 좋으니, 그 자산을 3D로 끌어오는 우회로인 셈.
- **다만 대가가 있다.** 시점별 렌더링 + 복원 + 5만 스텝 3DGS 최적화는 **점군 하나당 장면별 최적화**다. Grad-PU가 한 번 학습해두면 추론 0.4초인 것과 비교하면 성격이 완전히 다르다. 논문은 추론 시간을 보고하지 않는데, 실무 적용을 검토한다면 **이게 가장 먼저 물어야 할 숫자**다.
- **패치 분할 문제 지적은 타당하다.** 다만 그 해법이 "장면별 최적화"라면, 패치 경계 불연속을 없애기 위해 실시간성을 포기한 셈이다. 대규모 정적 자산(문화재 스캔, 3D 콘텐츠)에는 맞고, 로봇 실시간 인지에는 그대로 쓰기 어렵다 — 논문이 cs.RO에 제출됐다는 점을 감안하면 아쉬운 부분.
- 기하 정확도가 목적이면 [Grad-PU]({{< ref "/posts/grad-pu" >}}), **색과 지각 품질에 대규모 점군**이면 이쪽이다.

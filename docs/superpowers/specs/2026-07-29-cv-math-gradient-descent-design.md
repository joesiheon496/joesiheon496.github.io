# 컴퓨터 비전 수학 시리즈 — 3편 "경사하강법"

작성 2026-07-29. 대상 저장소 `joesiheon496.github.io` (Hugo + PaperMod).
1편 스펙: `2026-07-29-cv-math-transform2d-design.md`
2편 스펙: `2026-07-29-cv-math-svd-design.md`

## 목표

2편에서 닫힌 해로 한 번에 구했던 문제를 **반복해서 찾아가는** 방식으로 다시 풀고,
**왜 어떤 문제는 열 번에 끝나고 어떤 문제는 오천 번을 굴려도 안 끝나는지** 를
직접 만져보며 이해한다.

## 글의 축

한 문장으로 묶는다.

> **κ = σ₁/σ₂ 가 몇 번 반복해야 하는지를 정한다.**

학습률의 문턱, 지그재그, 전처리(중심화), 모멘텀이 전부 이 문장의 변주다.
1·2·3편이 한 줄로 이어진다.

| 편 | 문장 |
|---|---|
| 1편 | 행렬을 읽는다 |
| 2편 | σ₂/σ₁ 은 **답을 얼마나 믿을 수 있는가** 다 |
| 3편 | κ = σ₁/σ₂ 는 **몇 번 반복해야 하는가** 다 |

## 2편과의 연결

2편은 σ 를 **신뢰도**로 썼다. 3편은 같은 σ 를 **속도**로 쓴다. 연결 고리가 정확히 이것이다.

$$\kappa(\nabla^2 L) = \kappa(X^\top X) = \left(\frac{\sigma_1}{\sigma_2}\right)^2$$

2편에서 "작은 특이값을 나누는 것이 수치적 폭발의 정체" 라고 했던 그 σ₂ 가,
3편에서는 **제곱된 채로** 반복 횟수를 정한다. 이 등식은 테스트로 검증한다(§6-6).

두 번째 연결: 데모 2 의 닫힌 해가 2편의 `pseudoInverse2x2` 다. 회색 선(닫힌 해)과
진한 선(GD)을 같은 캔버스에 놓아 두 편을 나란히 보여준다. 이것도 테스트한다(§6-7).

### 목적함수를 바꾸는 이유 — 글에 명시해야 한다

2편 데모 2 는 **직교 회귀**(점에서 직선까지의 수직 거리)였고 SVD 로 풀었다.
3편은 **보통최소자승**(y 방향 잔차)으로 바꾼다.

$$L(a, b) = \sum_i (y_i - a x_i - b)^2$$

바꾸는 이유는 하나다. 직교 회귀의 손실은 각도에 대해 주기적이어서 **볼록하지 않다** —
최소점이 180° 간격으로 두 개 있고, 이 글의 중심인 수축률 `(κ−1)/(κ+1)` 은
볼록 이차함수에서만 성립한다. 같은 목적함수를 그대로 쓰면 데모 1 에서 세운 이론이
데모 2 에서 안 맞는다.

OLS 로 바꾸면 손실이 정확한 볼록 이차함수가 되고, Hessian 이 `2XᵀX` 라는 **상수 행렬**이
된다. 그래서 κ 가 시작점·반복수와 무관하게 데이터만으로 정해진다.

**글에서 이 전환을 한 단락으로 설명한다.** 슬쩍 바꾸고 넘어가면 2편을 읽은 독자가
"왜 선이 다르지" 에서 막힌다.

## 범위

**포함**
1. 경사하강법의 정의와 궤적 (데모 1)
2. 학습률의 문턱 `η > 2/λ_max` → 발산. 정확히 문턱이면 영원히 진동
3. **κ 가 수렴 속도를 정한다** — 수축률 `(κ−1)/(κ+1)`, 반복수 예측
4. 모멘텀 — 데모 1 의 토글 + β 슬라이더, 글 한 절 (κ → √κ)
5. OLS 를 GD 로 풀기 + 2편 닫힌 해와 대조 (데모 2)
6. 전처리: x 중심화가 κ 를 낮춘다 (데모 2 의 토글)

**제외** (별도 스펙)
- Adam, RMSProp, 학습률 스케줄
- 확률적 경사하강법(SGD), 미니배치 노이즈
- 뉴턴법·가우스-뉴턴·Levenberg–Marquardt 의 구현 (§7 에서 **말로만** 언급)
- 비볼록 최적화, 안장점, 딥러닝 학습 동역학

모멘텀에 별도 데모를 만들지 않는 이유: 데모 1 이 이미 궤적을 그리므로 토글 추가는
거의 공짜인데, 별도 데모로 만들면 데모 1 의 변주가 되어 독자가 새로 배우는 것이 적다.
데모 2 는 "합성 이차함수 → 실제 데이터" 라는 다른 그림을 준다.

## 3. 사전에 잡은 함정 — 구현이 반드시 지킬 것

### 3-1. κ = 1 에서 수축률이 NaN

κ=1 이면 최적 학습률이 1.0 이고 **한 스텝에 오차가 정확히 0** 이 된다. 그 다음 스텝의
비가 `0/0` = NaN 이다. 이론값 `(κ−1)/(κ+1)` 은 0 이므로 식이 틀린 게 아니라
**측정이 불가능한 것**이다.

→ readout 은 κ=1 근방에서 수축률·예상 반복수를 숫자로 찍지 않고 `한 번에 도달` 로 표시한다.
→ 테스트는 NaN 이 아님을 확인하고 궤적의 두 번째 점이 원점임을 본다.

### 3-2. η 가 정확히 문턱이면 발산이 아니라 진동

`η = 2/λ_max` 에서 그 축의 갱신이 `y ← y − 2y = −y` 가 되어 부호만 뒤집힌다.
크기가 그대로 유지되므로 400스텝 후에도 오차가 정확히 1.0 이다.

→ 발산 경고 판정은 `η > 2/λ_max` 로 한다. `≥` 로 하면 진동을 발산으로 잘못 표시한다.
→ 글에서 이 지점을 따로 다룬다. "문턱에서 정확히 무슨 일이 일어나는가" 는 좋은 이야기다.

### 3-3. κ 가 크면 GD 가 안 끝나는 것이 정상이다

κ=80708 에서는 20만 스텝에도 수렴하지 않는다. 이것은 버그가 아니라 이 글의 요점이다.

→ 데모 1·2 의 반복 슬라이더에 상한을 둔다(각각 §4, §5). 상한에서도 목표에 도달하지
못했으면 readout 이 **`미도달`** 을 명시한다. 아무 표시 없이 멈추면 독자가 버그로 읽는다.
→ 예상 반복수가 상한을 넘으면 숫자 대신 `> 상한` 으로 표시한다.

### 3-4. 중심화는 같은 직선을 준다 — 파라미터화만 다르다

중심화 여부와 무관하게 **OLS 의 답인 직선은 완전히 동일하다** (실측 환산 오차 1e-16~1e-12).
바뀌는 것은 `(a, b)` 의 좌표계와 조건수뿐이다.

- 중심화 ON: `y = a'(x − x̄) + b'` 를 푼다
- 원 좌표로 환산: `a = a'`, `b = b' − a' x̄`

→ 데모에서 토글을 켜도 **회색 선(닫힌 해)은 움직이지 않는다.** 진한 선(GD)만 빨라진다.
이게 요점이므로 회색 선이 흔들리면 구현이 틀린 것이다.
→ "닫힌 해와의 거리" readout 은 반드시 **환산 후 원 좌표에서** 계산한다. 중심화 좌표계의
`(a', b')` 와 원 좌표의 `(a, b)` 를 직접 비교하면 의미 없는 큰 값이 나온다.

### 3-5. 모멘텀 허용오차는 1e-9 로 잡을 수 없다

최적 파라미터의 heavy ball 은 임계감쇠라 고윳값이 복소수가 되고, 한 스텝 비에 미세한
진동이 남는다. 실측 편차가 이론 대비 **0.2%** 였다(κ=30 에서 0.692955 vs 0.691226).

→ 모멘텀 점근율 테스트만 **상대오차 1%** 를 쓴다. 나머지 항등식은 1e-9 를 유지한다.

## 4. 데모 1 — 등고선 위의 하강

손실은 `f(x, y) = ½(x² + κy²)`. Hessian 고윳값이 `1` 과 `κ` 이므로 조건수가 정확히 κ 다.
슬라이더가 곧 κ 이고, 다른 파라미터로 우회 계산하지 않는다.

### 학습률을 절대값이 아니라 문턱 대비 비율로 주는 이유

발산 문턱 `2/κ` 는 κ 에 따라 2.0(κ=1)에서 0.033(κ=60)까지 60배 움직인다. 절대 η
슬라이더 하나로는 두 끝을 동시에 담을 수 없다 — 범위를 [0.005, 0.35] 로 잡으면
**κ < 6 에서는 문턱에 도달조차 못 하고**(κ=1 의 문턱은 2.0), 범위를 [0.005, 2.0] 으로
넓히면 κ=60 의 관심 구간이 슬라이더 밑바닥 1.7% 에 뭉친다. 어느 쪽이든 §3-2 의
"문턱에서 무슨 일이 일어나는가" 를 만질 수 없다.

비율로 주면 **문턱이 항상 슬라이더의 1.0 지점**에 온다. κ 를 아무 값으로 놓아도
발산 경계가 같은 자리에 있고, 정확히 1.0 으로 맞추면 §3-2 의 영원한 진동을
직접 볼 수 있다. 최적 학습률은 비율 `κ/(1+κ)` 에 해당하며(κ=1 에서 0.5,
큰 κ 에서 1.0 에 근접) 전 구간에서 도달 가능하다. readout 에 최적 지점을 함께 표시한다.

**컨트롤**
- 슬라이더 `κ` ∈ [1, 60] — 등고선의 종횡비. 이 글의 주인공
- 슬라이더 `η/문턱` ∈ [0.05, 1.30] — 학습률을 **발산 문턱에 대한 비율**로 준다.
  실제 학습률은 `η = r · 2/κ` 이고 readout 에 절대값을 표시한다
- 슬라이더 `반복` ∈ [0, 300] — 궤적을 어디까지 그릴지. **상한 300** (§3-3)
- 체크박스 `모멘텀` + 슬라이더 `β` ∈ [0, 0.95]
- 시작점 드래그 (핸들 1개, 기존 `attachDrag` 재사용)

**그리기**
- 등고선 5개를 흐린 색으로 (`c` 를 등비로) — 64각형 타원
- GD 궤적을 `drawPath` 로. 각 스텝 점은 작은 원
- 최소점(원점)에 표식
- 발산하면 궤적이 화면을 벗어난다. 세계좌표 밖 점은 그리지 않고 readout 이 경고한다

**readout**
- κ, 현재 학습률의 절대값 `η = r · 2/κ`, 발산 문턱 `2/κ`, 최적값 `2/(1+κ)`
- **최적 학습률에서의** 수축률 `(κ−1)/(κ+1)` 과 예상 반복수 — 이 두 값은 슬라이더 `r` 이
  아니라 κ 만의 함수다. **"최적 η 기준" 이라고 라벨에 명시한다** (아래 주의)
- 현재 `r` 에서 궤적으로 실측한 수축률 — 이론값과 나란히 놓아 최적점에서 가장 빠른 것을 보여준다
- 목표(초기 오차의 1e-3) 도달 실측 반복수 — 300 안에 못 들면 `미도달` (§3-3)
- `r > 1` 이면 **발산 경고**, `r = 1` 이면 **"영원히 진동"** (§3-2)
- 모멘텀 ON: 생 GD 대비 반복수 배율, 그리고 이론 `(√κ−1)/(√κ+1)`

> ⚠️ 수축률 `(κ−1)/(κ+1)` 은 **최적 학습률에서만** 성립한다. 라벨 없이 찍으면
> 독자가 `r` 을 움직였는데 그 숫자가 안 변하는 것을 버그로 읽는다. κ=1 에서
> `한 번에 도달` 로 표시하는 것(§3-1)도 최적 η(= 비율 0.5)를 가정한 것이며,
> 다른 `r` 에서는 한 번에 도달하지 않는다.

**핵심 체험 세 가지** — κ 를 키우면 지그재그가 생긴다 / `r` 을 1.0 으로 밀면 진동이
멈추지 않고 그 위로는 터진다 / 모멘텀을 켜면 지그재그가 펴진다.

## 5. 데모 2 — 2편 직선맞춤 재방문

2편 `lsfit` 과 같은 세계좌표(`x, y ∈ [−3, 3]`)와 같은 점 6개 드래그를 쓴다.
목적함수만 OLS 로 바뀐다(§목적함수를 바꾸는 이유).

**컨트롤**
- 점 6개 드래그. 초기 배치는 **오른쪽 치우침 계열** (§2 — 토글 효과가 첫 화면에서 보이게)
- 슬라이더 `반복` ∈ [0, 400] — **상한 400** (§3-3)
- 체크박스 `x 중심화`

학습률은 슬라이더로 노출하지 않고 `η = 2/(λ_min + λ_max)` (최적값)으로 고정한다.
데모 1 이 이미 학습률을 다뤘고, 여기서는 **κ 만이 변수**여야 축이 흐려지지 않는다.

**그리기**
- 점 6개(핸들)
- **회색 선** — 닫힌 해. 2편 `pseudoInverse2x2` 로 구한다. 토글과 무관하게 불변(§3-4)
- **진한 선** — 현재 반복수에서의 GD 해
- y 방향 잔차를 세로 선분으로 (2편은 수직 거리였다 — 이 차이가 목적함수 변경을 눈으로 보여준다)

**readout**
- σ₁, σ₂ (설계행렬 `X = [x 1]` 의 특이값)
- **κ = (σ₁/σ₂)²** — 2편의 σ 가 제곱되어 들어오는 지점
- 현재 반복수, 닫힌 해와의 거리 (**환산 후 원 좌표에서**, §3-4)
- 1e-3 도달 예상 반복수 — 400 초과면 `> 400`
- 중심화 ON/OFF 의 κ 를 나란히 표시해 배율을 보여준다

**체험** — 점을 오른쪽으로 몰면 κ 가 뛰고 진한 선이 뒤처진다. `x 중심화` 를 켜면
회색 선은 그대로인데 진한 선이 즉시 따라붙는다.

## 6. optimize.js API 와 테스트

### API

이차함수 쪽
- `quadGrad(kappa, [x, y])` → `[x, kappa*y]`
- `gdPath({kappa, eta, beta = 0, start, steps})` → 점 배열 (길이 `steps+1`). `beta = 0` 이면 생 GD
- `contractionRate(kappa)` → `(κ−1)/(κ+1)`
- `momentumRate(kappa)` → `(√κ−1)/(√κ+1)`
- `optimalEta(kappa)` → `2/(1+κ)`
- `divergenceEta(kappa)` → `2/κ`
- `optimalBeta(kappa)` → `((√κ−1)/(√κ+1))²`
- `stepsToTarget(kappa, tol = 1e-3)` → 예측 반복수. **최적 학습률을 가정한 값**이다.
  κ=1 이면 `1`

OLS 쪽
- `olsDesign(points)` → `{X, y}`, `X` 는 `[[x, 1], …]`
- `olsKappa(points)` → `{s1, s2, kappa}` — 2편 `svd2x2` 를 재사용해 계산
- `olsClosed(points)` → `[a, b]` — 2편 `pseudoInverse2x2` 경로
- `olsGdPath({points, steps, center = false})` → `[a, b]` 배열 (원 좌표로 환산된 값)
- `centerPoints(points)` → `{points, xbar}`

`olsGdPath` 가 **원 좌표로 환산된 값을 돌려주는 것**이 규약이다. 호출자가 환산을
기억해야 하면 §3-4 함정을 데모마다 다시 밟는다.

### 테스트 10개

1. 수축률이 `(κ−1)/(κ+1)` 과 일치 — κ ∈ {2,10,30,50,100}, 실측 궤적 대조, **1e-9**
2. **κ=1 특수** — 수축률·예상 반복수가 NaN 이 아니고, 궤적의 두 번째 점이 원점
3. **발산 문턱** — `η = 2/κ` 정확히는 오차 유지(진동), `1.01 × 2/κ` 는 발산 (§3-2)
4. 예상 반복수가 실측과 ±2회 이내 — κ ∈ {2,10,30,50,100}
5. **모멘텀 점근율**이 `(√κ−1)/(√κ+1)` 과 **상대오차 1%** 이내 (§3-5)
6. **2편 교차검증** — `olsKappa().kappa` 가 `svd2x2(X)` 의 `(σ₁/σ₂)²` 와 **1e-12** 이내 일치
7. **2편 교차검증** — `olsClosed()` 가 `pseudoInverse2x2` 로 구한 해와 일치
8. GD 가 닫힌 해로 수렴 — 잘 조건화된 배치에서 **1e-12**
9. **중심화 불변** — 중심화 ON/OFF 의 닫힌 해가 원 좌표에서 동일(1e-9), 그리고 κ 가 낮아진다
10. 손실이 단조 감소 — `η < 2/λ_max` 이고 **`beta = 0`** 인 모든 스텝에서.
    모멘텀에서는 성립하지 않는다 (heavy ball 은 오버슛한다) — 이 테스트에 β 를 넣으면
    옳은 구현이 실패한다

6·7번이 두 편을 코드로 잇는 테스트다. 2편의 `preservation().keepsAngle` ↔ `σ₁=σ₂`
테스트와 같은 자리다.

## 7. 글 구조

1. 2편이 남긴 질문 — 닫힌 해가 있는데 왜 반복하나
2. 목적함수를 바꾼 이유 (직교회귀 → OLS, 볼록성)
3. 경사하강법이란 무엇인가 + **데모 1**
4. 학습률 — 문턱이 `2/λ_max` 고, 정확히 그 값이면 영원히 진동한다
5. **κ 가 속도를 정한다** — 수축률 식, §2 검증 표
6. 2편의 σ 가 제곱되어 돌아온다 + **데모 2**
7. κ 를 줄이는 두 가지 — 데이터를 고치기(중심화·정규화) / 계산을 고치기(모멘텀, κ→√κ)
8. 컴퓨터 비전에서 왜 중요한가 — 번들 조정, 2편 캘리브레이션 절의 재방문
   (체커보드 각도를 다양하게 = κ 를 낮추는 작업), LM 이 GD 와 가우스-뉴턴 사이를 오가는 이유
9. 정리 + 4편 예고

8절은 **말로만** 한다. 가우스-뉴턴·LM 을 구현하지 않는다(§범위).

## 8. 성공 기준

구현이 끝났다고 말하기 전에 실제로 확인한다.

1. `npm test` 전부 통과 (1·2편 29개 + 신규 10개 = 39개)
2. `hugo` 빌드 통과, 새 글이 `/posts/` 목록에 나온다 (**날짜를 미래로 적지 않는다** —
   미래면 Hugo 가 빌드에서 제외한다)
3. 수식이 KaTeX 로 렌더된다. **블록 수식 안에 `=` 를 홀로 한 줄에 두지 않는다** —
   1편에서 이것 때문에 수식 두 개가 조용히 깨졌다 (setext 제목 밑줄로 해석됨).
   인라인은 `\(...\)` 이고 `$...$` 를 쓰지 않는다
4. 데모 1: κ·`η/문턱`·반복·β 슬라이더와 모멘텀 체크박스가 동작. `r` 을 1 위로 올리면
   발산 경고가 뜨고, 정확히 1 이면 "영원히 진동" 이 뜬다. 수축률 readout 에
   "최적 η 기준" 라벨이 붙어 있다 (§4)
5. 데모 2: 점 6개 드래그, `x 중심화` 를 켜도 **회색 선이 움직이지 않는다**(§3-4),
   진한 선만 빨라진다
6. 두 데모 모두 κ 가 클 때 `미도달` 을 명시한다 (§3-3)
7. light / dark 양쪽에서 두 데모가 읽힌다. 캔버스 색은 `themeColors()` 로 읽고
   `onThemeChange` 로 재렌더한다 (하드코딩 금지)
8. 좁은 폭에서 레이아웃이 유지되고 터치 드래그가 동작한다
9. 기존 글 회귀 없음 (공백 제외 내용 비교). 1·2편 데모가 계속 동작한다
10. 데모 JS 의 외부 의존성 0. 외부 CDN 은 KaTeX 뿐

**작업 규약**: 구현은 `main` 이 아니라 새 브랜치에서 한다. 테스트는 **인자 없이**
`node --test` 로 돌린다 (`node --test tests/` 는 Node 24 에서 디렉토리를 모듈로
해석해 실패한다 — `npm test` 가 이미 그렇게 설정돼 있다). Hugo 빌드에는 `go` 가
PATH 에 필요하다: `export PATH="$PATH:/c/Program Files/Go/bin"`.

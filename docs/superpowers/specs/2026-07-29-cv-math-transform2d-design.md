# 컴퓨터 비전 수학 시리즈 — 1편 "2D 변환 행렬" + 인터랙티브 데모 하니스

작성 2026-07-29. 대상 저장소 `joesiheon496.github.io` (Hugo + PaperMod).

## 목표

수학을 잘 모르는 독자가 **파라미터를 직접 만지면서** 컴퓨터 비전의 수학을 이해하게 한다.
정적 그림이나 GIF 가 아니라 브라우저에서 도는 인터랙티브 데모를 쓴다.

이 스펙은 시리즈 전체가 아니라 **1편 + 재사용 하니스**만 다룬다.

## 독자

- 코드는 읽지만 수학 표기에 익숙하지 않은 개발자
- "행렬을 곱한다"는 말은 들었지만 그게 화면에서 무슨 일인지 모르는 상태
- 목표: 글을 덮은 뒤 "Affine 과 Homography 가 뭐가 다른가"에 손짓으로 답할 수 있다

## 범위

**포함**
1. KaTeX 수식 렌더링 (시리즈 전체의 선행 조건)
2. 인터랙티브 데모 하니스 (2D Canvas)
3. 1편 글: 2D 변환 행렬 — Rigid / Similarity / Affine / Homography

**제외** (각각 별도 스펙)
- 3D 회전 표현: Quaternion, Rodrigues, Lie algebra (SE(3), SO(3))
- SVD, 고유값/고유벡터
- 카메라 캘리브레이션, 투영 기하
- 최적화: Gradient Descent, Least Squares, Bundle Adjustment, Levenberg–Marquardt

하니스가 1편에서 검증되면 나머지 글의 제작 속도가 올라간다. 그것이 1편에 하니스를 묶는 이유다.

## 1. 수식 렌더링

### 설정

`hugo.toml` 에 Goldmark passthrough 확장을 켠다. 이걸 켜지 않으면 Goldmark 가 LaTeX 의
`_` 를 이탤릭으로 해석해 **수식이 조용히 깨진다.**

```toml
[markup]
  [markup.goldmark]
    [markup.goldmark.extensions]
      [markup.goldmark.extensions.passthrough]
        enable = true
        [markup.goldmark.extensions.passthrough.delimiters]
          block = [['\[', '\]'], ['$$', '$$']]
          inline = [['\(', '\)']]
```

구분자는 Hugo 공식 문서 값을 그대로 쓴다.

**인라인은 `\(...\)` 이고 `$...$` 가 아니다.** `$...$` 를 인라인에 넣으면 기존 글의
달러 표기(가격 등)가 수식으로 잡힐 위험이 있다. 저자 편의보다 기존 12편의 회귀 방지가 우선이다.

### 조건부 로드

KaTeX 는 `math = true` 인 글에서만 로드한다. `layouts/partials/extend_head.html` 에
`{{ if .Param "math" }}` 가드를 넣는다. 이 파일은 이미 Pretendard 폰트용으로 존재하고
jsdelivr `preconnect` 도 이미 있다.

로드 대상은 KaTeX CSS + JS + `auto-render` 확장이며, `renderMathInElement` 의 delimiters 를
위 passthrough 설정과 **일치시킨다**. 두 곳이 어긋나면 한쪽만 렌더된다.

## 2. 데모 하니스

### 파일

```
static/js/mathviz/core.js         캔버스 셋업, 월드↔픽셀 좌표변환, 격자,
                                  드래그 핸들, 슬라이더 생성, 행렬 표시, 테마 감지
static/js/mathviz/transform2d.js  1편 전용 데모 로직
static/css/mathviz.css            데모 레이아웃
layouts/shortcodes/demo.html      {{< demo name="transform2d" >}}
```

### 원칙

**일반 프레임워크를 먼저 만들지 않는다.** `transform2d.js` 를 실제로 동작시킨 뒤,
명백히 공유되는 것만 `core.js` 로 뽑는다. 무엇이 필요한지 모르는 상태의 추상화는 두 번 만들게 된다.

`core.js` 에 들어갈 후보 (1편 구현 후 확정):
- 월드좌표 ↔ 캔버스 픽셀 변환
- 격자 · 축 그리기
- 드래그 가능한 점: 히트 테스트, 포인터 이벤트, 터치 지원
- 슬라이더 행 생성 (라벨 · 값 표시 · 범위)
- 행렬 표시 (변경된 원소 강조)
- 테마 변경 감지 후 재렌더

### 의존성

데모 JS 는 **의존성 0**. 빌드 스텝 없음. 외부 CDN 을 쓰는 것은 KaTeX 뿐이다.
2D 변환에 p5.js/d3 는 과잉이고 페이지 무게만 늘린다.

### 다크모드

PaperMod 에 light/dark 토글이 있다. **캔버스 색을 하드코딩하면 한쪽 테마에서 안 보인다.**
`getComputedStyle` 로 CSS 변수를 읽어 그리고, 테마가 바뀌면 다시 그린다.

### 모바일

캔버스는 컨테이너 폭에 맞춰 반응하고, 드래그는 포인터 이벤트로 터치를 함께 받는다.
슬라이더는 좁은 폭에서 캔버스 아래로 쌓인다.

## 3. 데모 사양 (1편)

**데모는 하나로 통합한다.** 변환 클래스를 토글하면 자유도가 늘고, 슬라이더가 추가되고,
드래그 핸들 제약이 풀린다. 5개 데모를 따로 만드는 것보다 **"자유도가 늘어난다"는 감각**이
직접 전달된다. 이것이 이 글의 핵심 장치다.

### 캔버스

- 월드좌표 `[-2, 2] × [-2, 2]`, 격자 + 축 표시
- 원본 도형: 단위 정사각형 `(0,0) (1,0) (1,1) (0,1)` — 흐린 색으로 항상 표시
- 변환된 도형: 진한 색. **한 변을 다른 색으로 칠해 방향을 표시한다** (반사와 회전을 구분하려면 필요)

### 변환 클래스와 조작

| 클래스 | 자유도 | 슬라이더 | 드래그 핸들 |
|---|---|---|---|
| Rigid | 3 | θ, tx, ty | 평행이동 1개 + 회전 1개 |
| Similarity | 4 | θ, tx, ty, s | + 스케일 |
| Affine | 6 | θ, sx, sy, shear, tx, ty | 세 점 자유. **네 번째 점은 평행사변형 제약으로 따라온다** |
| Homography | 8 | 없음 | 네 점 전부 자유 |

두 가지 의도적 설계:

**Affine 에서 네 번째 점이 따라오는 것**이 "평행선이 보존된다"를 손으로 느끼게 하는 장치다.
설명 문장보다 강하다.

**Homography 에 슬라이더를 두지 않는다.** 8개 슬라이더는 무엇이 뭔지 알 수 없게 만든다.
대신 "네 꼭짓점을 끌어보세요"로 안내한다. 8자유도 = 네 점의 (x, y) = 8 이라는 대응이
그 자체로 핵심 통찰이다.

Affine 슬라이더는 행렬 원소 6개가 아니라 **분해 파라미터**(θ, sx, sy, shear, tx, ty)를 쓴다.
자유도 수는 같고 각 슬라이더가 의미를 갖는다.

### 양방향 동기화

드래그하면 슬라이더와 행렬 숫자가 갱신되고, 슬라이더를 움직이면 도형과 핸들이 갱신된다.
Homography 는 슬라이더가 없으므로 드래그 → 행렬 방향만 있다.

### 표시

- **3×3 행렬**: 실시간. 단위행렬에서 벗어난 원소를 강조
- **보존량 readout**: 길이비 · 각도 · 평행성이 유지되는지 실시간 ✓/✗ 와 수치

readout 이 이 데모의 결론부다. 클래스를 올릴 때마다 체크가 하나씩 꺼지는 것을 본다.

## 4. 글 구성

축은 변환 종류의 나열이 아니라 **"무엇이 보존되는가"** 다. 수학을 모르는 독자에게 이게 가장 잘 붙는다.

| 단계 | 보존 | 상실 | 자유도 |
|---|---|---|---|
| Rigid | 길이, 각도 | — | 3 |
| Similarity | 각도, 길이 비율 | 크기 | 4 |
| Affine | 평행선 | 각도 | 6 |
| Homography | 직선 | 평행 | 8 |

흐름:

1. **왜 좌표 변환을 숫자 9개로 쓰는가** — 규칙을 표로 적는 대신 행렬로 적는 이유
2. **동차좌표: 왜 3×3 인가** — 평행이동을 덧셈이 아니라 곱셈으로 만들려고. 2×2 로는 안 되는 이유를 먼저 보인다
3. **계층을 데모로 하나씩** — 각 단계에서 무엇이 늘고 무엇이 깨지는지
4. **CV 에서 homography 가 계속 나오는 이유** — 평면을 다른 평면으로 보내는 것이 카메라가 하는 일

수식은 KaTeX 로 쓰되, **모든 수식 앞에 그 수식이 무슨 일을 하는지 한 문장을 먼저 둔다.**
독자가 수식을 건너뛰어도 글이 이어져야 한다.

Front matter 에 `math = true`, `categories = ["프로그램"]`.

## 5. 성공 기준

구현이 끝났다고 말하기 전에 아래를 실제로 확인한다.

1. `hugo` 빌드 통과. 새 글이 `/posts/` 목록에 나온다 (미래 날짜 주의 — 미래로 적으면 Hugo 가 제외한다)
2. **기존 12편 회귀 없음** — passthrough 를 사이트 전역으로 켜므로 기존 글 렌더를 확인한다
3. 수식: 블록 `$$...$$` 과 인라인 `\(...\)` 이 모두 렌더된다
4. 데모: 4개 클래스 전환, 슬라이더 ↔ 드래그 양방향 동기화, 행렬·readout 실시간 갱신
5. **light / dark 양쪽에서 데모가 읽힌다**
6. 좁은 폭(모바일)에서 레이아웃이 깨지지 않고 터치 드래그가 동작한다
7. 데모 JS 는 외부 의존성 0

## 6. 후속

하니스가 검증되면 같은 틀로 확장한다. 다음 글 후보 순서:

1. SVD — 회전·스케일·회전 분해. 원이 타원으로 변하는 데모. 1편 하니스를 거의 그대로 쓴다
2. 경사하강법 / 최소자승 — learning rate 슬라이더로 진동·발산 체감
3. 카메라 투영 (Intrinsic/Extrinsic) — 3D 렌더가 필요하므로 하니스 확장 여부를 그때 판단
4. 3D 회전 표현 (Rodrigues, Quaternion, Lie algebra) — 3 번의 하니스 위에서

3 번에서 3D 가 필요해지면 그때 다시 스펙을 쓴다. 지금 3D 를 대비해 하니스를 일반화하지 않는다.

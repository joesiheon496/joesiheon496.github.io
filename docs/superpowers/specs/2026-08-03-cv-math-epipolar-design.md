## 글의 축

> **에피폴라 기하는 카메라 두 대가 같은 점을 봤다는 사실을 행렬 하나로 적은 것이다.**

6편은 카메라 한 대였다. 두 대가 되면 한 이미지의 점 하나가 다른 이미지에서
**직선 하나로 제한된다** — 그게 $x_2^\top F x_1 = 0$ 이다.

두 개의 매듭이 있다.
- **6편 매듭**: 에피폴은 *다른 카메라의 이미지*다. 6편의 "소실점은 방향이 정한다" 와
  같은 종류의 사실 — 카메라 중심이라는 한 점이 상대 이미지에 찍힌 것이다.
- **2편 매듭**: $F$ 를 대응점에서 푸는 8점 알고리즘이 **SVD 의 최소 특이벡터**다.
  2편이 "$A^\top A$ 의 고유분해" 로 SVD 를 소개했는데, 여기서 실제로 쓴다.

## 범위

**들어가는 것**
1. 카메라 둘 — 6편의 $K[R|t]$ 를 두 개로, 상대 자세 $R_{rel}, t_{rel}$
2. 에피폴라 제약 $x_2^\top F x_1 = 0$, $E = [t]_\times R$, $F = K_2^{-\top} E K_1^{-1}$
3. 에피폴 — $F$ 의 널공간이고, 동시에 다른 카메라 중심의 이미지 (6편 매듭)
4. $F$ 가 rank 2 인 이유, 그리고 강제하는 이유가 **정향도가 아니라 정의**라는 것
5. 8점 알고리즘 = SVD 최소 특이벡터 (2편 매듭), Hartley 정규화

**빼는 것** (8편 이후)
- 삼각오차·3D 복원
- $E$ 에서 $R, t$ 분해 (네 겹 모호성)
- RANSAC, 스테레오 정합, rectification

## 2. 사전 검증한 수치 — 프로토타입 실측

`camera.js` 를 그대로 import 해서 Node 로 측정했다. 구현이 이 값을 재현해야 한다.

**기준 설정**: $K$ 는 6편과 같다 ($f=500$, $c_x=c_y=240$, size 480).

### 2-1. 에피폴라 제약이 정확히 0 이다

카메라 1 `eye=(-2,-6,1.6)`, 카메라 2 `eye=(2,-6,1.6)`, 둘 다 `target=(0,0,0.8)`.
베이스라인 4.0000 m. 점 10개에서:

```
최대 |x2ᵀ F x1| = 4.441e-16       (F 원본)
              = 1.776e-15       (Frobenius 1 로 정규화한 F)
```

### 2-2. $F$ 는 정확히 rank 2 다

```
σ(F) = 4.260e-1, 1.337e-4, 0.000e+0
σ3/σ1 = 0.000e+0        det(F) = 0.000e+0
```

⚠️ $\sigma_2/\sigma_1 = 3.14\times10^{-4}$ 로 작다. rank 2 이긴 하지만 조건이 좋지 않다 —
3-2 참조.

### 2-3. 🔑 에피폴은 다른 카메라의 이미지다 (6편 매듭)

```
C1 을 cam2 에 투영 = (-1271.9524, 176.7544)   깊이 1.2549
C2 을 cam1 에 투영 = ( 1751.9524, 176.7544)   깊이 1.2549
null(F)  = ( 1751.9524, 176.7544)   ← cam1 의 에피폴, 일치오차 4.99e-10 px
null(Fᵀ) = (-1271.9524, 176.7544)   ← cam2 의 에피폴, 일치오차 5.33e-9 px
```

에피폴라 직선 5개가 에피폴에서 벗어난 거리 최대 **1.01e-9 px**.

### 2-4. 🔑 배치가 에피폴을 화면 안에 넣는다 — 데모 기본값이 좌우가 아니다

에피폴 위치 (화면 0\~480, ✓ 는 화면 안):

| 배치 | $e_1$ | $e_2$ | $\sigma_2/\sigma_1$ |
|---|---|---|---|
| 좌우 (스테레오) | (1752, 177) | (−1272, 177) | 3.14e-4 |
| 좌우 좁게 | (4563, 174) | (−4083, 174) | 2.67e-3 |
| **전진 (광축 방향)** | **(240, 190) ✓** | **(240, 140) ✓** | 5.37e-4 |
| **전진 + 약간 좌우** | **(333, 190) ✓** | **(437, 141) ✓** | 1.42e-4 |
| 수렴 (서로 안쪽) | (1081, 171) | (−601, 171) | 1.01e-4 |
| 전진 + 상하 | (240, 298) ✓ | (240, 361) ✓ | 9.26e-4 |

**데모 기본값은 `전진 + 약간 좌우`** — `eye1=(-0.5,-8,1.6)`, `eye2=(0.5,-4,1.6)`,
둘 다 `target=(0,0,0.8)`. 에피폴 둘이 다 화면 안이면서 좌우 대칭으로 보이지 않는다.
좌우 스테레오를 기본으로 두면 에피폴이 1752 px 로 나가 "직선들이 한 점에서 만난다" 가
화면에서 안 보인다.

### 2-5. 8점 알고리즘 — 잡음 없으면 정확하다

대응 8개, 정답 $F$ 와 스케일 무관 비교 $\lVert \hat F - F\rVert$:

```
정규화 O: 7.470e-16
정규화 X: 2.538e-13
```

### 2-6. 🔑 정규화가 고치는 것은 **조건수**다

대응 8개에서 계수행렬 $A$ 의 조건수:

```
정규화 X: cond(A) = 1.322e+5
정규화 O: cond(A) = 5.708e+1        → 2320배 개선
```

### 2-7. 🚨 정확도 개선폭은 **배치가 정한다** — 교과서가 뭉개는 지점

기하 오차(대칭 에피폴라 거리, px)로 재야 한다. 잡음 8개에 넣고 깨끗한 대응 12개로 평가,
시드 고정 60회 평균:

**전진 + 약간 좌우 (데모 기본값, 에피폴 화면 안)**

| $\sigma$ | 0.2 px | 0.5 px | 1.0 px | 2.0 px |
|---|---|---|---|---|
| 정규화 O | 0.4818 | 1.1818 | 2.3013 | 4.8269 |
| 정규화 X | 0.5847 | 1.4231 | 2.7194 | 5.9855 |
| 배율 | 1.21× | 1.20× | 1.18× | 1.24× |

**좌우 스테레오 (에피폴 1752 px 밖)**

| $\sigma$ | 0.5 px | 2.0 px |
|---|---|---|
| 정규화 O | 1.4230 | 6.1090 |
| 정규화 X | 7.4338 | 26.3550 |
| 배율 | **5.22×** | **4.31×** |

**조건수는 항상 2320배 좋아지는데, 정확도 이득은 배치에 따라 1.2배에서 5배까지 다르다.**
데모에 `배치` 라디오와 `정규화` 토글을 두어 이 대비를 직접 보게 한다.

### 2-8. 🚨 rank 2 강제는 **정확도를 개선하지 않는다** — 초판 스펙이 틀렸다

초판은 "$\sigma_3 \ne 0$ 이면 에피폴이 정의되지 않는다" 고 적었다. 재보니 **아니다.**
잡음 수준 5개 × 배치 2개를 40회씩 평균한 실측 (전진 + 약간 좌우 배치):

| $\sigma$ | 에피폴 오차 강제 O / X | 기하 오차 강제 O / X | $\sigma_3/\sigma_1$ 강제 O / X |
|---|---|---|---|
| 0.5 px | 6.53 / **6.30** | 1.067 / **0.898** | 3.3e-11 / 1.7e-8 |
| 1 px | 13.18 / **12.83** | 2.044 / **1.816** | 3.4e-11 / 3.1e-8 |
| 2 px | 27.59 / **27.37** | 4.193 / **3.749** | 3.0e-11 / 8.3e-8 |
| 5 px | 81.06 / **78.64** | 11.117 / **10.481** | 4.7e-11 / 7.5e-7 |
| 10 px | 167.46 / **157.69** | 24.666 / **21.510** | 2.1e-10 / 3.3e-6 |

강제는 $\sigma_3/\sigma_1$ 을 **1000배쯤 줄이는 일은 확실히 한다** (1.7e-8 → 3.3e-11).
그런데 **모든 잡음 수준에서 강제하지 않은 쪽이 같거나 약간 낫다.** 두 지표 다 그렇다.

그래서 강제하는 이유는 정확도가 아니다:
1. **유효한 $F$ 의 정의**가 $\det F = 0$ 이다. rank 3 짜리는 어떤 카메라쌍으로도
   실현되지 않는 행렬이다
2. **8편이 요구한다** — $E$ 에서 $R, t$ 를 분해하려면 rank 2 여야 한다

글에서 이걸 정직하게 쓴다. "정확도가 좋아진다" 고 쓰면 실측과 어긋난다.

⚠️ 강제해도 $\sigma_3$ 가 정확히 0 은 아니다. 정규화 좌표계에서 누른 뒤
$F \leftarrow T_2^\top F T_1$ 로 되돌리면 부동소수 오차가 6e-11 쯤 남는다. 버그가 아니다.

### 2-9. 🚨 에피폴이 화면 밖이면 위치 추정이 3자리 불안정하다

같은 잡음 0.5 px, 20회 평균 에피폴 위치 오차:

| 배치 | 에피폴 위치 | 오차 |
|---|---|---|
| 전진 + 약간 좌우 | $u = 333$ (화면 안) | **6.5 px** |
| 좌우 스테레오 | $u = 1752$ (화면 밖) | **7914 px** |

세 자리 차이다. 에피폴이 이미지에서 멀면 $F$ 의 작은 오차가 널공간 방향을 크게
흔든다. **데모 기본값을 전진 배치로 두는 두 번째 근거**이고, 2-7 의 "정규화 이득이
스테레오에서 크다" 와 같은 뿌리다 — 둘 다 에피폴이 먼 배치가 병들었다는 이야기다.

## 3. 사전에 잡은 함정

### 3-1. 🚨 정규화 효과를 행렬 차이로 재면 "효과 없음" 이 나온다

처음 $\lVert \hat F - F \rVert$ (둘 다 Frobenius 1 로 정규화)로 쟀더니 잡음
0.2\~2.0 px 에서 배율이 **1.0×** 였고 $\sigma=2$ 에서는 정규화 안 한 쪽이 더 좋았다.
지표가 틀렸다 — 잡음이 지배하는 구간에서 행렬 성분 차이는 기하적 의미가 없다.

**대칭 에피폴라 거리(px)로 재야 한다.** 그러면 1.2\~5.2배가 나온다 (2-7).

### 3-2. 잡음 0 에서의 배율을 인용하지 않는다

$\sigma=0$ 에서 기하 오차 배율이 1631× 로 찍히지만 양쪽 다 `0.0000 px` 다.
아주 작은 수를 더 작은 수로 나눈 값이라 의미가 없다. 글에 쓰지 않는다.

### 3-3. 새 수치 코드가 필요하다 — `transform.js` 는 건드리지 않는다

2편의 `svd2x2` 는 2×2 전용이다. 7편은 두 개가 더 필요하다:
- **9×9 대칭 고유분해** (야코비) — $A^\top A$ 의 최소 고유벡터, 8점 알고리즘의 핵심
- **3×3 SVD** — rank 2 강제용. $F^\top F$ 의 고유분해로 만든다 (2편과 같은 방법)

둘 다 새 파일 `epipolar.js` 에 둔다. `transform.js` 와 `camera.js` 는 import 만 한다.

### 3-4. $E$ 와 $F$ 의 스케일은 자유다

비교·테스트는 전부 스케일·부호 무관으로 해야 한다 (Frobenius 1 로 정규화 후
$\min(\lVert a-b\rVert, \lVert a+b\rVert)$).

### 3-5. 6편의 규약을 그대로 쓴다

이미지 좌표 뷰는 world 의 y 를 거꾸로 준다(`ymin > ymax`), 모든 3D 선은
`projectPolyline` 을 지난다, 색은 `themeColors()` 에서만, 물결표는 `\~`,
인라인 수식은 `\(...\)`, 블록 수식에 `=` 를 홀로 두지 않는다.

### 3-6. 🚨 교과서 근거를 실측 없이 옮겨 적지 말 것

이 스펙에서 초판 주장 **두 개**가 실측으로 뒤집혔다.

1. "Hartley 정규화가 정확도를 크게 올린다" — 지표를 잘못 잡아 처음엔 "효과 없음" 이
   나왔고(§3-1), 옳은 지표로 재니 효과는 있지만 **배치가 크기를 정했다**(§2-7)
2. "rank 2 를 강제해야 에피폴이 정의된다" — **틀렸다.** 강제하지 않은 쪽이 모든
   잡음 수준에서 같거나 약간 낫다(§2-8). 강제하는 이유는 정확도가 아니라 정의다

둘 다 "교과서가 그렇게 말하니까" 로 스펙에 적었던 것이고, 재보니 달랐다. 6편에서도
같은 일이 세 번 있었다(단정이 NEAR 와 모순, dolly zoom 이 카메라를 지면 아래로,
데모 손잡이가 잡히지 않음). **§2 가 존재하는 이유가 이것이다** — 글에 들어갈 문장은
전부 실측으로 뒷받침돼야 한다.

## 4. 데모 (계획 없이 직접 구현)

**데모 1 — 에피폴라 직선** (`epilines`, 2패널)
좌: 카메라 1 이미지, 점을 끌 수 있다. 우: 카메라 2 이미지, 그 점의 에피폴라 직선 + 에피폴.
`배치` 라디오(전진+좌우 / 좌우 스테레오 / 전진), 카메라 2 위치 슬라이더.
readout: $\lvert x_2^\top F x_1\rvert$, 에피폴 좌표, 화면 밖이면 경계 화살표(6편 방식).

**데모 2 — 8점으로 $F$ 패기** (`eightpoint`, 2패널)
대응 8개에 잡음을 넣고 $\hat F$ 를 복원한다. `정규화` 토글, `잡음 σ` 슬라이더,
`배치` 라디오. readout: `cond(A)`, 기하 오차(px), $\sigma_3/\sigma_1$.
정규화를 껐다 켜며 배치를 바꾸면 1.2배와 5배가 숫자로 갈린다 — 2-7 이 화면에서 재현된다.

### 3-7. 🚨 에피폴라 직선을 지면 격자와 같은 색으로 그리지 말 것

배포 후 사용자가 "에피폴라 직선이 엉뚱한 방향이다" 라고 보고했다. 수학은 옳았다 —
직선이 대응점을 지나는 거리가 모든 경우에 1e-13 이었다. 문제는 **색**이었다.

두 데모 모두 에피폴라 직선을 `c.grid` 로 그렸는데 그게 **지면 격자와 같은 색**이다:
- 데모 1: 다발 직선과 양방향 직선이 `c.grid`
- 데모 2: 정답 $F$ 의 기준 직선이 `c.grid`

지면 격자는 **격자 자신의 소실점**으로 모이고 에피폴라 직선은 **에피폴**로 모인다.
서로 다른 점이다. 색이 같으면 독자가 격자선을 에피폴라 직선으로 읽고, 그러면 방향이
완전히 엉뚱해 보인다. 6편의 §3-13(기본값이 주장하는 대상을 화면에 안 보이게 했다)과
같은 종류 — **수치는 다 맞는데 화면에서 읽을 수 없는** 결함이고 자동 검증으로는 안 잡힌다.

고친 배색: 격자 `grid`, 박스 `muted`, **에피폴라 직선 `accent3`(녹)**,
끌고 있는 직선·복원 $\hat F$ `accent`(청), 에피폴·대응점 `accent2`(적).
글에도 색 이름을 적고, 격자와 에피폴라 직선이 다른 점으로 모인다는 주의를 넣었다.

**일반 규칙**: 한 캔버스에 의미가 다른 선 종류가 둘 이상이면 **색을 먼저 배정하고**
그 배정을 글에 적는다. 같은 색 두 종류는 없는 것과 같다.

### 3-8. 두 데모는 **서로 다른 배치**를 기본값으로 쓴다

배포 후 사용자가 "뷰가 안 맞는다" 고 보고한 것의 두 번째 원인이다. 전진 배치는
카메라 2 가 두 배 가까워서 같은 박스가 **70 px 대 153 px (배율 2.17)** 로 보인다.
전진 운동이 실제로 그런 것이지만 두 패널이 짝으로 읽히지 않는다.

**데모 1 은 감수한다.** 에피폴을 화면 안에 두는 배치가 전진 8/4 뿐이다 — 배율을 1 에
가깝게 하는 배치는 실측 8종 전부 에피폴을 화면 밖으로 밀어낸다. 데모 1 의 주제가
에피폴이므로 포기할 수 없다. 대신 글에 이 대가를 명시했다.

**데모 2 는 좌우 스테레오를 기본값으로 쓴다.** 에피폴이 보일 필요가 없기 때문이다 —
cond(A) 와 기하 오차가 주제다. 스테레오로 두면:

| | 전진 8/4 | 좌우 스테레오 ±2/6m |
|---|---|---|
| 박스 배율 | 2.17 | **1.00** |
| 풀이용 8점이 화면 안 | 8/8 (한 점은 우측 5 px) | 8/8 |
| 정규화 배율 (30회) | 1.19배 | **4.44배** |

정규화 효과가 더 크게 드러나서 이 데모의 논지에도 오히려 맞다. 배치를 ±1.8/7m 로
바꾸면 여유가 더 나지만(4.92배) §2-7 의 실측 표가 ±2/6m 기준이라 그대로 두었다 —
**데모가 보여줄 숫자와 글에 적힌 숫자가 어긋나지 않는 것이 우선이다** (6편 §3-13 교훈).

**일반 규칙**: 데모마다 주장하는 것이 다르면 기본 배치도 달라도 된다. 대신 어느 데모가
어느 배치인지 글에 적는다 — 안 적으면 독자가 같은 그림을 기대하고 어긋난다고 읽는다.
